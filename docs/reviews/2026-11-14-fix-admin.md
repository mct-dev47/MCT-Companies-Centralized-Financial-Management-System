## Summary
This change set implements administrative and operational fixes across backend and frontend services. Key improvements include production frontend URL derivation to prevent invalid localhost invitation links, resilient audit log querying during Supabase outages, Zod CSP compatibility configuration, and accessibility attributes on modal inputs. However, two blocking issues require resolution prior to merge: an untracked validation configuration file that will break CI builds, and an image error handler that triggers an infinite loop when fallback assets fail. In addition, the removal of reauthentication checks on company deletion violates security specification 0039 AC-16.

## Blockers
### 🔴 Untracked validation module breaks production build, `frontend/src/lib/validation/zod.ts:1`
**Problem**: The newly created file `frontend/src/lib/validation/zod.ts` is untracked in git. It is imported by `frontend/src/main.tsx:1`, `frontend/src/lib/validation/auth.ts:1`, `frontend/src/lib/validation/employee.ts:1`, and `frontend/src/lib/validation/recovery.ts:1`.
**Why it matters**: Any clean checkout, CI runner, or production Vercel deployment will fail immediately with module resolution errors because the file is missing from git history.
**Suggested fix**: Stage and commit `frontend/src/lib/validation/zod.ts` to git.

### 🔴 Infinite loop risk in image error fallbacks, `frontend/src/pages/EmployeePage.tsx:276` and `frontend/src/components/employee/ViewCompanyModal.tsx:547`
**Problem**: The image error handlers compare `target.src !== logo2Url` before resetting `target.src = logo2Url`. In browser DOM implementations, `target.src` returns a fully qualified absolute URL, while `logo2Url` is a relative Vite bundle path. As a consequence, `target.src !== logo2Url` continuously evaluates to true.
**Why it matters**: If `logo2Url` fails to load, returns a 404, or suffers network interruption, the browser repeatedly re-triggers the error event synchronously. This locks the JavaScript event loop and freezes the user browser tab.
**Suggested fix**: Clear the error handler prior to reassigning the fallback source using `target.onerror = null` followed by `target.src = logo2Url`.

## Major
### 🟠 Destructive company deletion bypasses reauthentication requirement, `backend/app/api/v1/endpoints/companies.py:328`
**Problem**: The endpoint dependency `_reauth: AuthenticatedUser = Depends(require_reauthentication)` was removed from `delete_company`.
**Why it matters**: Spec 0039 Acceptance Criterion AC-16 mandates that sensitive destructive actions, specifically company deletion, require fresh credential reauthentication. Company deletion cascades through all associated financial records, ledgers, leases, and bank accounts. Removing reauthentication allows any administrative session token, including stale or remembered sessions, to execute irreversible data destruction without credential re-verification.
**Suggested fix**: Re-enable `require_reauthentication` on the backend route and implement the client-side reauthentication modal prompt in `ViewCompanyModal.tsx` before dispatching the DELETE request.

### 🟠 Global DialogContent autofocus override breaks accessibility, `frontend/src/components/ui/dialog.tsx:51`
**Problem**: `DialogContent` overrides `onCloseAutoFocus` globally by preventing default behavior and calling `document.activeElement.blur()`.
**Why it matters**: WAI-ARIA and WCAG 2.1 modal dialog guidelines require returning keyboard focus to the triggering element upon dialog closure. Blurring active focus resets focus to `document.body` for every modal across the application, disorienting keyboard and screen reader navigation.
**Suggested fix**: Remove the global blur override from `DialogContent`. If a specific dialog has issues with lingering focus outlines, apply `onCloseAutoFocus` selectively to that specific dialog component.

## Minor
### 🟡 Unguarded z.config invocation risks initialization crash, `frontend/src/lib/validation/zod.ts:4`
**Problem**: `z.config({ jitless: true })` is called directly without verifying that `z.config` exists on the resolved Zod module.
**Why it matters**: `z.config` is a new API introduced in Zod 4. If any environment or dependency bundle resolves Zod 3, calling `z.config` throws an uncaught TypeError that halts application startup.
**Suggested fix**: Add a type guard checking whether `typeof (z as any).config === 'function'` before invoking it.

### 🟡 Hardcoded production Render URL in WebSocket fallback, `frontend/src/services/websocketService.ts:105`
**Problem**: When not running on localhost, `websocketService.ts` defaults `wsUrl` directly to `wss://mct-companies-centralized-financial.onrender.com/ws` if `VITE_WS_URL` is undefined.
**Why it matters**: Staging environments, custom domain deployments, or preview branches will silently route real-time WebSocket traffic to the production Render instance instead of their corresponding backend.
**Suggested fix**: Derive the WebSocket origin dynamically from the current host or provide explicit configuration warnings in non-production deployments.

### 🟡 WebSocket reconnection halts permanently after threshold, `frontend/src/services/websocketService.ts:217`
**Problem**: The service stops reconnecting once `reconnectAttempts` reaches 10, remaining in an offline state until page reload.
**Why it matters**: When users experience intermittent network dropouts lasting more than two minutes, the application never recovers real-time synchronization automatically once connectivity is restored.
**Suggested fix**: Attach a listener for the window `online` event to reset `reconnectAttempts` and trigger reconnection.
